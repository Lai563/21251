## 一、30 秒電梯簡報

> 恐怖遊戲最怕玩家出聲，但玩家從來沒有「真的」被要求安靜。
>
> 《勿聲》把麥克風音量變成唯一的控制器：你必須出聲，才能用回聲「看見」漆黑的空間；但每一次出聲，都會引來聽覺獵食的怪物。
>
> **看得見的代價，是被聽見。**
>
> 零學習成本、零外接設備、開網頁就能玩——這是所有評審與觀眾在 10 秒內就能理解的互動。

## 二、遊戲概念

### 2.1 核心體驗

玩家在完全黑暗的環境中探索。視覺幾乎無用，**世界是靠聲音「畫」出來的**：出聲時，聲波會從玩家位置向外擴散，碰觸牆面與物件後折返，短暫勾勒出環境輪廓（聲納視覺）。

同一時間，怪物不需要看見你——**牠只聽得見你**。

### 2.2 核心張力（雙面刃設計）

| 玩家行為 | 獲得 | 代價 |
|---|---|---|
| 保持安靜 | 安全、怪物失去目標 | 全黑，看不見路，只能摸黑前進 |
| 低聲呢喃 | 小範圍微光，可辨識腳邊 | 聲紋殘留 3 秒，怪物開始緩慢靠近 |
| 大聲吼叫 | 大範圍照明、可震退逼近的怪物 | 全區怪物被吸引，進入追逐狀態 |
| 長時間不出聲 | 怪物散去 | 缺氧，角色自動喘氣（被動發出聲響） |

**玩家永遠在「看見」與「活著」之間交換籌碼。** 這是本作唯一、也是全部的樂趣來源。

### 2.3 一句話定位

> 一款「你越想知道周遭有什麼，就越可能被吃掉」的恐怖遊戲。

## 三、世界觀與敘事

**背景**：一座因礦災被封閉的深山療養院。事故後，院內所有人失去聽覺以外的感知，某種東西開始以「聲音」為食。

**玩家角色**：一名聽覺異常敏銳的調查員，醒來時發現自己身處全黑的地下層，手上只有一支故障的手電筒（無法使用）。

**反派「聽者」**：看不見、不會跑，但只要偵測到聲源就會朝該方向直線前進，沿途破壞一切。牠不追人，牠追聲音。

**敘事手法**：不靠過場動畫，靠**聲音線索**——走廊盡頭傳來的廣播、錄音帶、牆後的敲擊聲。玩家必須「聽」才會知道故事，而聆聽本身也意味著安靜地待著。

## 四、核心玩法系統

### 4.1 聲量值（Volume Meter）

麥克風輸入的音量即時轉換為 0～100 的「聲量值」，並以三種顏色回饋於畫面邊緣：

| 區間 | 狀態 | 世界反應 |
|---|---|---|
| 0–20 | 靜默 | 無照明，怪物失去目標，緩慢遊蕩 |
| 21–55 | 低聲 | 微光照明，怪物朝聲源緩慢移動 |
| 56–85 | 呼喊 | 中範圍照明，怪物加速 |
| 86–100 | 尖叫 | 全區照明、可震退怪物，所有敵人鎖定玩家 |

### 4.2 氣息條（Breath）

出聲會消耗氣息，靜默時緩慢回復。氣息歸零時角色強制喘氣 3 秒（不受控的聲響），這是本作的「裝彈時間」——**勇氣有額度，安靜有代價**。

### 4.3 聲紋殘留（Sound Trail）

每一次出聲都會在地面留下 3～5 秒的「聲紋」，怪物會沿著殘留路徑追蹤。玩家可以刻意在錯誤方向留下聲紋來誤導敵人——**這是本作唯一的「戰鬥技巧」，本質上是一種聲音版的誘餌佈局**。

### 4.4 聲納視覺美學

- 畫面不採用傳統黑暗＋手電筒，而是**聲波環形擴散**的即時輪廓線稿
- 出聲時畫面「亮起」如超音波影像，安靜時畫面幾乎全黑
- 視覺風格：單色線稿 + 顆粒雜訊 + 輕微鏡頭呼吸感

### 4.5 死亡與重試

被「聽者」接觸即死亡，但**沒有讀取畫面**：死亡瞬間畫面轉黑，僅剩心跳聲，3 秒後從最近的「安靜點」重生，怪物重置。降低挫敗感，維持節奏。

## 六、操作與回饋

- **唯一輸入**：麥克風音量（選配：滑鼠轉向、WASD 移動）
- **聽覺回饋**：聲量越大，環境殘響越長、心跳越快、怪物腳步聲越近
- **視覺回饋**：畫面邊緣聲量環、氣息條、聲紋地面殘留、怪物靠近時的畫面撕裂
- **觸覺／體感回饋**（加分項）：低頻震動讓玩家「感覺」自己被聽見

## 七、技術可行性

| 項目 | 說明 |
|---|---|
| 音量取得 | 瀏覽器原生麥克風存取 + 即時音量分析（RMS / 分貝），**無需語音辨識、無需連網** |
| 延遲 | 音量反應約 20～50ms，恐怖遊戲節奏完全夠用 |
| 辨識難度 | 不做語音轉文字，因此不受口音、語言、雜訊語意干擾 |
| 隱私 | 音訊**全程留在本機**，不上傳、不錄存——可作為提案的信任賣點 |
| 相容性 | Chrome / Edge / Firefox 桌面版；手機可作延伸 |
| 開發引擎 | WebGL（Three.js 或 Unity WebGL），單頁即可執行 |
| 硬體需求 | 一般筆電 + 耳機麥克風即可，**零門檻** |

### 7.1 麥克風校準流程（開場 15 秒）

1. 偵測環境底噪，建立個人化門檻
2. 請玩家「安靜 3 秒 → 小聲說一句 → 大喊一次」完成三段校準
3. 校準結果存於本機，下次免重做

> 此設計同時解決「展場吵雜」與「玩家麥克風靈敏度差異」兩大風險。

## 八、市場與競品分析

| 作品 | 互動方式 | 本作差異 |
|---|---|---|
| *Don't Scream* | 不能出聲（單向懲罰） | 本作讓「出聲」同時是**唯一解法與唯一風險** |
| *One Hand Clapping* | 音量控制平台跳躍 | 本作把同一機制移入恐怖類型，壓力層級完全不同 |
| *Phasmophobia* | 語音辨識觸發 | 本作不需辨識、不受語言限制，且**安靜本身就是玩法** |
| 傳統恐怖遊戲 | 手電筒／電池管理 | 本作把「資源」換成人類最原始的東西：**氣息與聲音** |

**差異化一句話**：市面上沒有遊戲讓「音量」同時是照明、武器、與死亡原因。

### 目標客群

- 主要：18–35 歲、喜歡恐怖實況與派對遊戲的玩家
- 次要：遊戲實況主與短影音創作者（**本作極適合觀看**：玩家越緊張，觀眾越興奮）
- 延伸：展覽／校園活動的體感互動攤位

## 九、為什麼這個提案會贏（競賽說服點）

1. **10 秒聽懂**：評審不需教學就能理解玩法
2. **零門檻**：不需要 VR、不需要體感裝置、不需要註冊
3. **現場示範效果極強**：試玩者的尖叫就是最好的宣傳
4. **技術風險低**：只用到瀏覽器原生音量分析，不需 AI 模型
5. **主題統一**：全部機制都從「音量」長出來，沒有拼湊感
6. **隱私友善**：不錄音、不上傳，可放心在公開場合展示

## 十四、附錄：評審問答預備

**Q：這不就是「不能出聲」的老梗嗎？**

A：剛好相反。多數同類作品是「禁止出聲」的單向懲罰；本作把出聲變成**唯一能看見世界的方法**，玩家被迫主動承擔風險，這是主動取捨而非被動忍耐。

**Q：為什麼不用語音辨識？**

A：辨識帶來延遲、口音問題與隱私疑慮。音量是不需翻譯的語言，全球玩家都能玩，也讓開發風險降到最低。

**Q：只有一個機制，會不會很單薄？**

A：機制只有一個，但**決策密度很高**：何時出聲、多大聲、往哪個方向留聲紋、氣息還剩多少。四章各自改變「聲音的物理條件」（空曠、密閉、水面、對峙），讓同一個機制持續產生新問題。
