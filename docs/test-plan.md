## 1. 目的與範圍

### 1.1 目的

1. 以可重現的方式證明 68 條 AC 中每一條都已被驗證；數值門檻一律以 `acceptance-criteria.md` §2 為準。
2. 在 RC 前找出會阻斷交付的 S1／S2 缺陷。
3. 讓三位 tester 能依文件獨立執行，不依賴原作者口頭說明。

### 1.2 In scope

- `js/core` 純邏輯：聲量映射、區間、氣息、聲紋、聽者 AI、Boss、校準、章節 gate、Session。
- `GameSession` 整合：四章完整流程、死亡重生、鍵盤模式全通關。
- 靜態檢查：禁用 API、外部依賴、繁中文案、placeholder。
- 瀏覽器煙霧：載入、音訊權限、Canvas 渲染、console、網路。
- 效能：基準機 fps、dt 異常、記憶體。
- 無障礙與人工驗收：字幕、降低動態、視覺化音量、聽障通關、文案。
- 15 人試玩 KPI。

### 1.3 Out of scope

- 伺服器端（本作沒有）。
- 手機／平板完整支援（plan §7 列為延伸）。
- 語音辨識（本作不使用）。
- 美術主觀品質、劇情文本的文學評價。
- 行銷素材、簡報、展場硬體架設。

## 2. 測試層級與策略

| 層級 | 名稱 | 工具 | 範圍 | 目標 |
|---|---|---|---|---|
| L1 | 單元 | Node 20 `node --test` | `js/core` 純函式／狀態機；注入時鐘與 RNG | 語句覆蓋 ≥85%、分支 ≥80% |
| L2 | 整合 | Node 20 + `GameSession` | 固定 60Hz 模擬完整章節、死亡重生、鍵盤全通關 | 每 suite <30s；四章可抵結局 |
| L3 | 靜態檢查 | `node --check` + 自訂掃描 | 禁用 API、外部 URL、繁中、placeholder、檔案大小 | 零違規 |
| L4 | 瀏覽器煙霧 | Playwright（僅開發依賴） | Chromium／Firefox、假麥克風、鍵盤模式、效能、隱私 | 零 console error、零外部請求 |
| L5 | 人工驗收 | 人工 checklist | 無障礙、文案、手感、隱私、15 人試玩 | AC 全數簽核 |

**策略**：核心邏輯盡量下沉到 L1／L2，瀏覽器層只驗證「接線」與視覺／音訊整合，避免用 Playwright 測數學。所有時間相關測試使用假時鐘，禁止 `sleep` 等待。

### 2.1 測試金字塔比例（工時）

- L1：40%
- L2：30%
- L3：10%
- L4：15%
- L5：5%（不含 15 人試玩籌備）

## 4. 執行方式

### 4.1 指令

```bash
# L1 單元
node --test tests/unit

# L2 整合
node --test tests/integration

# L3 靜態檢查
node tools/static-check.mjs

# L4 瀏覽器（Chromium）
npx playwright test --project=chromium

# L4 瀏覽器（Firefox）
npx playwright test --project=firefox

# 手動／煙霧
python -m http.server 8080
# 開啟 http://localhost:8080
```

若專案提供 `package.json`，上述指令應包成 `npm run test:unit`、`test:integration`、`test:static`、`test:e2e`；沒有 `package.json` 時以直接指令為準。

### 4.2 CI 門檻

| 時機 | 執行 | 通過條件 |
|---|---|---|
| 每次 push／PR | L1 + L2 + L3 | 全綠，<3 分鐘 |
| 每晚 | L4 Chromium + Firefox | 全綠；console error 0；外部請求 0 |
| RC 前 | L1–L5 + 人工 | 見 §11 退出準則 |
| 展場前一日 | 基準機全流程彩排 | Release Checklist 全勾 |

### 4.3 假麥克風設定（Chromium）

```bash
--use-fake-ui-for-media-stream
--use-fake-device-for-media-stream
--use-file-for-fake-audio-capture=fixtures/audio/calibration.wav
```

Firefox 的假麥克風不穩定，**Firefox 以鍵盤模式做煙霧測試**；麥克風流程由 Chromium + 人工耳麥補足。

### 5.4 幀率與 dt

| 情境 | dt | 預期 |
|---|---|---|
| 144fps | 6.94ms | 位移與 60fps 一致（誤差 ≤5%） |
| 60fps | 16.67ms | 基準 |
| 30fps | 33.33ms | 位移一致，無穿牆 |
| 卡頓 | 100ms | 夾在 0.1s，最多 5 步 |
| 切分頁 | 250ms／1000ms | 不得快轉、不得瞬間耗氣、不得跳過死亡 |
| dt=0 | 0 | 不除以零、不 NaN |

### 5.5 校準與儲存

| 情境 | 預期 |
|---|---|
| 底噪 −60／−40／−20dB | 門檻相應提高，靜默不誤判 |
| 小聲 −30dB | 映射到 21–55 |
| 大喊 −6dB | 映射到 86–100 |
| 無訊號／全靜音 | 校準失敗，提供重試／鍵盤 |
| `hush.calibration.v1` 損毀 JSON | 自動失效，要求重校，不崩潰 |
| 版本不符 | 視為失效 |
| localStorage 停用／配額滿 | 記憶體 fallback + 提示，不崩潰 |

### 5.6 網路與隱私

| 情境 | 預期 |
|---|---|
| DevTools Offline | 完整可玩（localhost 已載入） |
| 阻擋 `*` 外部網域 | 零失敗請求、零 console error |
| 檢查 localStorage／IndexedDB／Cache | 無音訊 blob、無 base64 音訊 |
| 暫停／離開頁面 | 麥克風音軌停止、指示燈熄滅 |

### 10.1 協作規則

- T1 發現邏輯缺陷 → 開票給程式，附最小重現與 seed。
- T2 發現瀏覽器／效能缺陷 → 附瀏覽器版本、裝置、frame trace、截圖。
- T3 發現文案／無障礙缺陷 → 附截圖、WCAG 對照、建議文案。
- 每日 15 分鐘 triage；S1 立即拉群，不等每日會議。
- 週五合併「AC 狀態表」，未測項目必須有負責人與日期。

## 11. 缺陷分級與退出準則

### 11.1 缺陷分級

| 級別 | 定義 | 範例 | 處理 |
|---|---|---|---|
| S1 | 阻斷：崩潰、隱私外洩、無法通關、<30fps、資料遺失 | 鍵盤模式卡 Ch2、外部請求、重生點錯誤 | 立即修，RC 前必須關閉 |
| S2 | 主要：核心機制錯誤但有 workaround | 震退距離偏差、字幕缺方向 | RC 前修或 waiver |
| S3 | 次要：視覺／文案／手感 | 對齊、錯字、音效平衡 | 可延後至 next |
| S4 | 輕微：建議 | 動畫曲線、選單間距 | backlog |

### 11.2 進入準則（Entry）

- 功能開發完成，主要章節可跑。
- L1／L2 可執行，CI 綠。
- 無已知 S1。
- 測試環境與 fixture 就緒。

### 11.3 退出準則（Exit）

1. P0 40 條全部通過（不可豁免項見 AC §4.1）。
2. P1 23 條至少 20 條通過；其餘 ≤3 條有 workaround 與 PM＋QA waiver。
3. P2 不阻斷，列入 known issues。
4. 無 S1、無未關閉 S2。
5. 三瀏覽器煙霧綠、隱私掃描零違規、30fps 下限達標。
6. Release Checklist 全勾且有簽核。

- W9 結束：P0 100%、P1 ≥90%、30fps 實證。
- W10：只修 S1／S2，不新增功能。
