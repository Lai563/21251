## 0. 文件效力

1. 本文件是交付驗收的唯一功能基準。`plan.md` 描述產品意圖；若兩者衝突，產品意圖以 `plan.md` 為準，**數值常數與驗收門檻以本文件 §2 為準**。
2. 本文件所有數值均為「專案決議」。實作若需調整，必須同步修改本文件並經 PM 簽核，否則測試一律以現行版本判定。
3. 交付形態依專案決議採 **Canvas 2D + Web Audio**（`plan.md` §7 原列 WebGL，已替換）。不得引入外部素材、CDN、外部字型或執行期網路請求。
4. 每一條 AC 都必須能被自動或人工重現。無法重現的敘述視為不合格的 AC。
5. 本文件 §2 的常數是 **QA 驗收基準**。若 `product-spec.md`／`architecture.md` 的【預設】數值與此不同，實作前必須由 PM 召開一次對齊，指定唯一來源；未對齊前，不得以「文件不同」作為測試失敗的豁免。

## 1. 驗收基準環境

| 項目 | 基準 |
|---|---|
| 交付 | 靜態網站：`index.html` + ES modules；以 localhost 靜態伺服器執行 |
| 為何不用 `file://` | `getUserMedia` 需要 secure context；`file://` 不在驗收範圍 |
| 基準機 | Windows 11、4 核 8 執行緒、8GB RAM、內顯、1920×1080、Chrome 最新穩定版 |
| 音訊 | 有線耳麥、48kHz；`echoCancellation=false`、`noiseSuppression=false`、`autoGainControl=false` |
| 次要瀏覽器 | Edge、Firefox 最新兩個穩定版；macOS 14 + Chrome 為次要 |
| 視窗 | 1920×1080（主要）、1366×768（次要）、DPR 1 與 2 |
| 網路 | 可完全斷網；不得有任何非 localhost 請求 |

> 展場若使用喇叭，回授會讓麥克風誤判。驗收與展示一律使用耳機；此為環境前提，不是程式豁免理由。

## 2. 名詞與專案決議常數

### 2.1 聲量四區間

| 聲量 | 區間 | HUD 文字 | 顏色（僅輔助） | 聲納半徑 | 聽覺半徑 |
|---|---|---|---|---|---|
| 0–20 | 靜默 | 靜默 | 灰 `#6B7280` | 0 | 0 |
| 21–55 | 低聲 | 低聲 | 藍 `#3B82F6` | 4 格 | 6 格 |
| 56–85 | 呼喊 | 呼喊 | 琥珀 `#F59E0B` | 9 格 | 12 格 |
| 86–100 | 尖叫 | 尖叫 | 紅 `#EF4444` | 當前房間全部 | 全圖 |

- 「格（tile）」為邏輯單位；基準解析度下 1 格 = 32 world px。
- 邊界為整數且含端點：20 屬靜默、21 屬低聲、55 屬低聲、56 屬呼喊、85 屬呼喊、86 屬尖叫。
- 顏色不得為唯一辨識方式；必須同時有文字與非顏色圖形。

### 2.2 核心常數

| 常數 | 值 | 備註 |
|---|---|---|
| 聲量輸出 | 0–100 整數 | 超出範圍夾住 |
| 聲量更新率 | ≥20Hz | 音訊到狀態延遲 p95 ≤80ms |
| 氣息上限 | 100 | 不得為負 |
| 氣息變化 | 低聲 −4/s、呼喊 −10/s、尖叫 −18/s、靜默 +6/s | 容差 ±10% |
| 強制喘氣 | 3.0s ±0.1s | 等效聲量 ≥86；期間不可控 |
| 喘氣結束 | 氣息 = 100 | 0.5s 內不得再觸發 |
| 聲紋產生間隔 | ≤0.2s | 聲量 ≥21 時 |
| 聲紋壽命 | 低聲 3s、呼喊 4s、尖叫 5s | ±0.2s |
| 聲紋上限 | 64 節點 | 超過丟最舊 |
| 聲納淡出 | 0.8s ±0.1s | 停止出聲後 |
| 玩家速度 | 2.4 格/s | 直線 |
| 聽者速度 | 巡邏 0.8／調查 1.2／追逐 1.8 格/s | 不得高於玩家 |
| 震退距離 | ≤5 格內觸發；推開 ≥2 格／0.4s | 暈眩 2.0s |
| 震退再觸發 | 同一聽者 1.0s 內最多一次 | 防止連續尖叫鎖死 |
| 接觸死亡 | 距離 ≤0.6 格 | 需連續碰撞偵測 |
| 重生 | 3.0s ±0.2s | 無敵 1.5s |
| 安靜點 | 半徑 1 格、聲量 ≤20 持續 1.0s | 最近者優先 |
| 校準 | 15s ±1s（3/3/4/5s） | 底噪／安靜／小聲／大喊 |
| Ch4 對峙 | 4 格內、≥56 聲量、累計 6.0s | 衰減 50 點/s |
| 幀時間 | 目標 60fps、下限 30fps | p95 ≤33ms |
| dt 上限 | 0.1s／每幀最多 5 固定步 | 分頁返回不得快轉 |

### 2.3 章節與機制對應

| 章 | 場景 | 必教機制 | 驗收重點 |
|---|---|---|---|
| 1 醒 | 地下鍋爐室 | 低聲照路、氣息管理 | 不用尖叫即可通關 |
| 2 走廊 | 療養院主棟 | 吼叫震退、聲紋誘餌 | 兩個 gate 皆為必要 |
| 3 水室 | 淹水地下層 | 水中聲傳更遠 | 半徑 ×1.5、聲紋 +1s |
| 4 聽者 | 教堂式中庭 | 連續吼叫壓過聲源 | 6s 累計、衰減、接觸死亡 |

## 4. 驗收阻斷條件（Delivery Blockers）

### 4.1 通則

1. **任何 P0 未通過，不得交付。**
2. 以下為**不可豁免**的阻斷項；即使時程不足也不得簽核放行：
   - 核心可玩性：AC-02、AC-03、AC-06、AC-10、AC-11、AC-15、AC-17、AC-19、AC-20、AC-21、AC-22、AC-24。
   - 死亡與流程：AC-26、AC-27、AC-30、AC-31、AC-32、AC-33、AC-34。
   - 無麥克風可通關：AC-42、AC-43。
   - 校準：AC-38、AC-39。
   - 隱私與離線：AC-45、AC-46。
   - 效能下限與時間穩定：AC-50、AC-51。
   - 繁中與可理解性：AC-63、AC-64、AC-65。
3. **隱私或外部網路任一項失敗（AC-45、AC-46），無論優先級，立即阻斷交付。**
4. P1 未通過：最多 3 條，且每條需有 workaround、known issue 記錄、PM 與 QA 共同簽核；不得以 P1 waiver 掩蓋 P0。
5. P2 未通過：列入 known issues 與下一版 backlog，不阻斷。
6. 任何 S1 缺陷（見 `test-plan.md` §11）未關閉，不得進入 RC。
